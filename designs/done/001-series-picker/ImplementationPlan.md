The design files beside this plan are the truth; this plan only says how to build them.

Build 001 as one PR into feature/recorded-shows. Everything it calls already exists in the app: getCuratorSeries, createSeries, updateEpisode with CuratorEpisodeUpdate(series: .join / .makeStandalone), the builder's lazy creation (resolveEpisodeId) and serialized save queue (enqueueSave), SeriesSchedule for reading and writing weekly rules, and StationSchedulingSettings for the station time zone. ## PR 1 — feature: let curators put a show in a series, move it, or start a new series from the show builder

From a Show's builder a curator can add the Show to a Series, switch it to another, take it out, or create a new Series on the spot and have the Show join it, without changing when the Show airs. Works on a brand-new unsaved Show too, creating it only when a Series choice is committed.

**Changes**

- Add PlayolaRadio/Views/Pages/SeriesPickerSheet/ with SeriesPickerSheetModel.swift, SeriesPickerSheetView.swift and SeriesPickerSheetTests.swift. The model is an @MainActor @Observable ViewModel owning all text (title, subtitle, row labels, "Remove from <Series>"), loading/failed state and actions; the view only renders it and has no control flow.
- Add PlayolaRadio/Views/Pages/SeriesDetailsSheet/ with SeriesDetailsSheetModel.swift, SeriesDetailsSheetView.swift and SeriesDetailsSheetTests.swift, New Series mode only (design 002 adds editing). Present it from the picker as a nested sheet so Cancel or swipe returns to the same picker.
- Add a seriesPicker case to PlayolaSheet and render it in MainContainer's standard sheet branch. Give that .sheet an onDismiss: MainContainerModel remembers the sheet it presented and, when SwiftUI reports the dismissal finished, calls the picker model's dismissed closure, which calls ShowBuilderPageModel.seriesSheetsDismissed(). The builder presents a kept Series failure with presentSaveAlert(for:) (skipping cancellations) only once both the change has finished and seriesSheetsDismissed() has been called, in whichever order they happen, because the builder's alert sits under the sheets and can't show while they are open. Implement ShowBuilderPageModel.seriesRowTapped() behind canChangeSeries (so loading and multi-airing Shows stay disabled), and add an isSavingSeries flag that canChangeSeries also requires to be false: the builder sets it when it receives a Series change (a pick, a remove, or the New Series hand-off, which only happens after createSeries has succeeded, so a createSeries failure never touches the builder's state) and clears it at the same moment the dismissal rule below resolves (the change has finished and the sheets are dismissed), so the picker can never be reopened over a pending change and present the picker with the builder's stationId, its confirmed episode.show, and the builder's display title.
- Picker load: on appear call api.getCuratorSeries for the station, keep server order, drop isOneTime rows. Row subtitle is SeriesSchedule(rrule:)?.text, "No schedule" for nil, "Custom schedule" when SeriesSchedule can't read it. While loading show title, subtitle and a ProgressView; rows and New Series appear together. On failure report via NetworkErrorClassifier conventions, show a toast, and show only New Series (plus Remove when in a Series). Each presentation loads afresh.
- Picking and removing live in ShowBuilderPageModel and go through enqueueSave, so they share the existing queue with renames and content changes and an unsaved Show is created exactly once by resolveEpisodeId. The picker dismisses before the request; the builder's Series row changes only from the server's response and the following refresh (no optimistic update). Send api.updateEpisode(jwt, id, CuratorEpisodeUpdate(series: .join(seriesId))) or .makeStandalone; merge the response with mergingMetadata(from:) so segments and airings are kept. Tapping the checked Series dismisses and sends nothing. Every Series change (pick, remove, New Series join) uses enqueueSave(alertsOnFailure: false) and keeps the returned failure (as appendVoicetrackToShow already does); runChange's existing loadEpisode inside the queue is the only refresh, with none added after dismissal.
- New Series form: empty name, Every week, no days, 7:00 PM. Save enabled only when the trimmed name is non-empty and, for Every week, at least one day is chosen. Days and Time hidden for No schedule (entries kept if the curator switches back). Days display Sunday-first. Time is wall-clock in the builder's StationSchedulingSettings time zone, falling back to America/Chicago, with no zone label; build the rule with SeriesSchedule and send nil rrule for No schedule.
- New Series save: disable Save and show a ProgressView in its place, and block Cancel, swipe and edits until done. Call api.createSeries with the trimmed name; on failure show a PlayolaAlert with the server message and keep the sheet and its input. On success post recordedShowsChanged, then hand the new Series to the builder, which creates the Show if unsaved and joins it through the same queue. Save stays busy through creation, join and the queue's refresh; when that finishes (success or failure) close both sheets, and any kept failure is shown by the dismissal rule above. This covers both a failed join and a failed creation of an unsaved Show.
- Use a one-shot completion per picker presentation so a late response can't dismiss a newer sheet. Keep the existing recordedShowsChanged behaviour for successful saves.
- Register every new file in PlayolaRadio.xcodeproj/project.pbxproj (app and test targets, explicit file references). Add changelog.d/series-picker.md with a plain-English Changes bullet. Add qa/ux/series-picker as a visual case covering the three mockups, and run make ux-evidence for it.

**Tests**

- ShowBuilderPageTests: the Series row opens the picker in Draft, Scheduled, Locked and Aired, and does nothing while an existing Show loads or for a Show that airs more than once; with a gated updateEpisode, canChangeSeries is false from the pick until the change finishes and the picker's dismissed closure has run (tested in both orders), so seriesRowTapped presents nothing in between, and it is true again after both a success and a refusal.
- SeriesPickerSheetTests: Add-to-a-series and Change-series text with the Show's name; the current Series checked; "Remove from <Series>"; one-time wrappers hidden; server order kept; weekly, No schedule and Custom schedule labels; a station with no Series shows only New Series.
- SeriesPickerSheetTests with a gated getCuratorSeries: progress view while loading; on failure a toast and New Series (plus Remove when in a Series); reopening loads again; a cancelled load shows no toast.
- ShowBuilderPageTests: join, switch and remove send the right CuratorEpisodeUpdate; the picker dismisses before the response; the Series row keeps its old value until the server confirms; segments and airings are unchanged; a refusal refreshes the Show once through the queue and leaves presentedAlert nil until seriesSheetsDismissed() is called, then shows the server's message (trigger the dismissal through the picker model's wired dismissed closure, not by calling seriesSheetsDismissed() directly); with dismissal finishing before the refusal arrives, the alert shows as soon as the refusal arrives; tapping the checked Series sends nothing.
- ShowBuilderPageTests for an unsaved Show: opening and dismissing both sheets calls none of createSeries, createStandaloneEpisode, createEpisodeInSeries or updateEpisode (the picker's getCuratorSeries read is allowed); picking a Series calls createStandaloneEpisode once and then joins; New Series creates the Series before the Show; a failed creation leaves the builder unsaved; a failed join keeps the created Show's id; a rename queued alongside a Series pick still creates only one Show.
- SeriesDetailsSheetTests: Save disabled for an empty or spaces-only name and for Every week with no day; the sent name is trimmed; day toggling; Days and Time hidden for No schedule with nil rrule; default 7:00 PM; Cancel makes no request.
- MainContainerTests: the presented series picker is kept until its sheet's onDismiss runs, for both a programmatic dismissal (presentedSheet set to nil) and an interactive one; its dismissed closure is called exactly once; when a newer sheet replaces it, only the picker that was actually dismissed is notified.
- SeriesDetailsSheetTests: Tuesday and Thursday at 8:00 PM sends FREQ=WEEKLY;BYDAY=TU,TH;BYHOUR=20;BYMINUTE=0 and the picker then reads "Every Tuesday and Thursday at 8pm", with the test's time zone set away from Central and with station settings missing.
- SeriesDetailsSheetTests: Save stays busy through creation, join and refresh, getCuratorEpisode is called exactly once after the join, and a second tap is ignored; a createSeries failure keeps the sheet and input and leaves the builder's isSavingSeries false with no builder request sent; failure → retry → success creates the Series, joins it and re-enables the row once the sheets are dismissed; failure → Cancel → picking an existing Series sends that join normally; a failure after the Series exists (a failed join, and a failed creation of an unsaved Show) closes both sheets and sets the builder's presentedAlert to the server's message only after the picker's wired dismissed closure runs (assert it is nil before), and the new Series is listed when the picker reopens.
- Every new suite uses @Suite(.freshSharedState) and @MainActor, withDependencies for the API, expectNoDifference/expectDifference for values, and async gates instead of sleeps. Run the full ShowBuilderPageTests, MainContainerTests, both new suites, SeriesScheduleTests and APIClientRecordedShowsTests with xcodebuild, plus make lint and make changelog-check.

**"Done when" items it delivers**

- 1. Tapping the builder's Series row opens the picker in every builder state (Draft, Scheduled, Locked, Aired); the row stays disabled while an existing Show is loading, for a Show that airs more than once, and while a Series change is saving.
- 2. A standalone Show's picker matches "Add to a series"; a Show in a Series' picker matches "Change series", with its Series checked and "Remove from <Series>".
- 3. The picker lists every Series on the station and never a hidden one-time Series; each row shows its schedule in words, "No schedule", or "Custom schedule".
- 4. Picking a Series puts the Show in it, closes the sheet, and the builder's Series row shows the Series name; the Show's air time is unchanged.
- 5. "Remove from <Series>" makes the Show standalone and the builder's Series row reads "Add to a series"; the Show's air time is unchanged.
- 6. New Series matches its mockup; Save stays disabled until it has a name and, for "Every week", at least one day; Days and Time disappear for "No schedule".
- 7. Saving a New Series creates it, the Show joins it, and the builder shows its name; the new Series then appears in the picker.
- 8. A Series made "Every week" on Tuesday and Thursday at 8:00 PM reads "Every Tuesday and Thursday at 8pm" in the picker, in Central time regardless of the phone's time zone.
- 9. Cancel or swipe on either sheet changes nothing; tapping the checked Series closes the picker and sends nothing.
- 10. While the Series list loads the picker shows a progress view; if it fails, a toast shows and the picker still offers "New Series" (and "Remove from <Series>" when in a Series).
- 11. While New Series saves, Save is a disabled progress view; if creating the Series fails the sheet stays open with its input; if the Series is created but joining fails, both sheets close and the builder shows the Show as the server has it.
- 12. On a brand-new unsaved Show, opening and dismissing the Series sheets creates nothing; committing a Series choice creates the Show once and puts it in that Series, and later changes edit that same Show.
- 13. A server refusal shows an alert with the server's message, and the builder then shows the Show as the server has it.
